## はじめに：「インプットはしたのに模試で取れない」

「参考書は読んだ。動画も見た。なのに模試をやると6割止まり…」
SAA学習者の多くがぶつかる壁です。これは**才能や勉強量の問題ではなく、やり方の問題**であることがほとんど。

実際、私が学習相談を受けてきた範囲でも、6割で停滞している人の大半は「努力不足」ではなく「努力の向きがズレている」だけでした。向きを直すと、数週間で7割・8割に届く人を何人も見ています。
この記事では、点が取れない人に共通する5つのパターンと、その具体的な処方箋を示します。

## 共通パターン5つ

### パターン①：インプット偏重、演習不足

参考書を完璧にしようとして、問題を解く量が圧倒的に足りない。
「もう少し理解してから問題に…」と先延ばしし、いつまでも演習に入れないタイプです。

→ **処方箋**：インプット3：演習5（残り2は復習）の比率に。**問題を解きながら覚える**に切り替える。
人は「思い出す」ときに記憶が定着します。読むだけでは「分かった気」になるだけで、引き出せません。

> 現場のひとこと：私自身、最初の1冊を読み切るより前に問題集を開いて、分からない単語が出たら本に戻る、という順番にしてから一気に伸びました。

### パターン②：答えの「丸暗記」

「この問題の答えはB」と覚えるだけ。少し問われ方が変わると崩れる。

→ **処方箋**：**「なぜBなのか」「なぜA・C・Dは違うのか」**まで説明できるようにする。これが本物の理解。
本番は同じ問題が出るわけではありません。**選択肢4つすべてに理由をつけられる**状態が、応用の効く知識です。

選択肢を潰すときのテンプレ：

```
選んだ理由   : Bは〇〇という要件（マネージドで運用最小）を満たすから
A を切る理由 : 運用負荷が高い／要件と方向が逆
C を切る理由 : コストが過剰／オーバースペック
D を切る理由 : そもそも機能要件を満たさない
```

### パターン③：間違いを分析していない

解いて丸付けして終わり。同じ間違いを繰り返す。

→ **処方箋**：間違いを **「知らなかった／読み間違えた／迷って外した」** の3つに分類。分類ごとに対策が違います。

| 間違いの種類 | 原因 | 処方箋 |
| --- | --- | --- |
| 知らなかった | 知識の穴 | 該当範囲をインプット＋ハンズオンで補う |
| 読み間違えた | 設問の読解 | 条件語に線を引く習慣（パターン④へ） |
| 迷って外した | 判断軸の不在 | AWSの設計思想に照らす（後述） |

「知らなかった」ばかりなら教材を進める、「迷って外した」が多いなら知識でなく**判断軸**の問題、というように打ち手が変わります。

### パターン④：問題文を正確に読めていない

「**最もコスト効率が良い**」「**最小の運用で**」「**可用性を最優先で**」などの**条件語**を見落とす。
同じサービス群が並んでいても、この一語で正解が変わります。

→ **処方箋**：条件語に線を引く癖をつける。よく出る条件語の対応イメージ：

| 条件語 | 寄りやすい方向 |
| --- | --- |
| 最もコスト効率が良い | サーバーレス／スポット／適切なストレージクラス |
| 運用負荷を最小に | マネージドサービス（RDS, Fargate, Lambda 等） |
| 可用性/耐障害性を最優先 | マルチAZ／冗長化／自動復旧 |
| 最小権限 | IAMロール／きめ細かいポリシー |
| 疎結合にしたい | SQS／SNS／EventBridge |

### パターン⑤：サービスの「目的の違い」が曖昧

マルチAZとリードレプリカ、SQSとSNS、NLBとALB…の違いが頭の中で混ざっている。

→ **処方箋**：混同しやすいペアを「**目的**」で整理した早見表を作り、繰り返し確認する。

| ペア | 目的の違い（ざっくり） |
| --- | --- |
| マルチAZ vs リードレプリカ | 前者は可用性（待機系）／後者は読み取り性能のスケール |
| SQS vs SNS | 前者はキュー（1対1で溜める）／後者はPub/Sub（1対多で配る） |
| ALB vs NLB | 前者はL7（HTTP/パス振り分け）／後者はL4（高スループット/固定IP） |
| Security Group vs NACL | 前者はステートフル/インスタンス単位／後者はステートレス/サブネット単位 |

「機能」ではなく「**どんな課題を解くために存在するか**」で覚えると、初見の問題でも当てに行けます。

## 点が伸びる人の勉強サイクル

```
1. 問題を解く（時間も計る）
2. 答え合わせ＋「なぜ正解／なぜ他は不正解」を4択すべて確認
3. 間違いを3分類してノート化（知らない/読み違い/迷い）
4. 弱いカテゴリを参考書・公式Black Belt・ハンズオンに戻って復習
5. 数日空けて同じ範囲を再度解く（定着確認）
```

このサイクルを回すと、**点数は後からついてきます**。

### 1日の学習配分（目安）

時間が限られている社会人向けの一例です（あくまで目安。自分の弱点で調整を）。

```
平日 60〜90分
  └ 問題演習 40分 → 振り返り＆ノート 20〜30分 → 弱点インプット 残り
休日 2〜3時間
  └ 模試1セット → 全問の解説精読 → 弱点ハンズオン
```

「解きっぱなし」を作らないのが最大のコツ。**解く時間より振り返る時間を惜しまない**こと。

## 「2択で迷う」を減らすには

本番でもよくある「最後の2択」。ここで効くのが**AWSの設計思想**です。

- コスト最適化 ／ マネージドサービス優先 ／ 最小権限 ／ 疎結合・冗長化 ／ 運用の自動化

2択に絞れたら、設問の条件語と上の思想に照らします。
例：「運用負荷を最小に」とあって、EC2自前構築 と マネージドサービス で迷ったら——思想は迷わず後者を指します。

> 現場のひとこと：実務でも設計レビューでまったく同じ判断軸を使います。試験勉強は、実は現場の判断トレーニングそのものです。

## メンタル面のアドバイス

- 模試の点数に一喜一憂しない。**伸びしろの地図**だと捉える（低い分野＝次に伸びる分野）
- 6割→8割は、正しいやり方なら**短期間で到達できる**ことが多い
- 「分からない」は悪ではない。分からないを1つずつ潰すのが勉強
- 模試は**本番と同じ時間で通しで解く**練習も入れる（時間配分・集中力も実力のうち）

## 想定FAQ

**Q. 模試は何回くらい回せばいいですか？**
A. 回数より「同じ模試を、説明できるまで潰したか」が重要です。新しい模試を次々こなすより、**1セットを完璧に説明できる**状態を作る方が伸びます。

**Q. 何割取れたら本番を受けていいですか？**
A. 一概には言えませんが、目安として本番形式の模試で安定して合格ラインを上回り、かつ「なぜその答えか」を説明できているなら自信を持っていい段階です。点数だけでなく**理解の安定**を見ましょう。

**Q. ハンズオンは必要ですか？**
A. 「知らなかった」系の間違いが多いなら効果大です。手を動かすと、サービスの目的と挙動が腹落ちし、丸暗記から抜けられます。

## まとめ

模試で取れない原因は、たいてい次の5つ：

1. 演習不足 → 演習を主役に（インプット3：演習5）
2. 丸暗記 → 4択すべてに「なぜ」を説明できるように
3. 間違いを分析しない → 3分類でノート化し打ち手を変える
4. 問題文を読めていない → 条件語に線を引く
5. 目的の違いが曖昧 → 「目的」で早見表を作って整理

やり方を変えれば、点数は必ず伸びます。焦らず、サイクルを回していきましょう。
