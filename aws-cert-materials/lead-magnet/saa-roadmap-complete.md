## 📖 はじめに ── このガイドについて

このガイドを手に取ったあなたは、きっとこんな状況ではないでしょうか。

- 「AWSの資格を取りたいけど、何から手をつければいいか分からない」
- 「働きながらだと時間がない。最短で受かりたい」
- 「ただ合格するだけでなく、現場で使える力もつけたい」

このガイドは、**現役エンジニアが「自分が今からSAAを取り直すならこうする」**という視点でまとめた、8週間（週6〜8時間）の学習ロードマップです。

市販の教材と違うのは、**「試験には出ないが現場で必須」の視点**を各所に散りばめている点。合格を「ゴール」ではなく「スタート」にするための地図です。

### 対象とする資格
**AWS Certified Solutions Architect – Associate（SAA）**
AWS認定の中で最も人気が高く、転職・キャリアの土台になる資格です。

### このガイドが向いている人
- IT/開発の基礎が少しある人（完全未経験は+2〜4週間を見込む）
- 働きながら・週末中心で学習したい人
- 暗記でなく「理解」で受かりたい人

---

## 🎯 学習の3原則（これだけは守る）

合格者を何人も見てきて分かった、**伸びる人の共通点**を3つにまとめました。

### 原則① 「暗記」ではなく「理解」で覚える
AWSのサービスは200以上。丸暗記は不可能だし、シナリオ問題で崩れます。
**「このサービスは何のためにあるか」**を一言で言えるようにする。これが最強の勉強法です。

### 原則② インプットよりアウトプットを多く
参考書を読むだけでは受かりません。比率の目安は **インプット3 : 問題演習5 : ハンズオン2**。
**問題を解く時間が主役**です。

### 原則③ 必ず手を動かす（ハンズオン）
1サービスにつき最低1回、実際にコンソールで触る。
用語が「自分の言葉」に変わり、記憶への定着が段違いになります。

# 📅 週ごとの詳細プラン

---

## 第1週：全体像をつかむ＋環境準備

### この週で学ぶこと
- AWSの主要カテゴリ（コンピュート / ストレージ / DB / ネットワーク / セキュリティ）の俯瞰
- リージョンとアベイラビリティーゾーン（AZ）の概念
- 責任共有モデル（AWSとユーザー、どちらが何を守るか）
- SAA試験ガイド（公式）に一度目を通す

### 今週のハンズオン
- [ ] AWSアカウントを作成する
- [ ] **AWS Budgetsで予算アラートを設定する**（最重要・最優先）
- [ ] マネジメントコンソールを一通り触り、主要サービスの場所を把握

### つまずきポイント
- いきなり細部に入ると挫折する。**まず「地図」を眺める**意識で
- リージョン/AZの違いが曖昧なまま進むと後で混乱する

> 💼 **現役エンジニアのひとこと**
> 勉強を始める前に**必ず予算アラートを設定**してください。検証でうっかり課金が膨らむ事故は、合格者でもやります。これは試験対策であると同時に、現場でも「新アカウントを作ったら真っ先にやること」です。

---

## 第2週：コンピューティング & ネットワーク

### この週で学ぶこと
- **EC2**：インスタンスタイプ、AMI、購入オプション（オンデマンド/リザーブド/スポット）
- **VPC**：サブネット（パブリック/プライベート）、ルートテーブル、IGW、NATゲートウェイ
- **セキュリティグループ vs NACL**：ステートフル/ステートレスの違い

### 今週のハンズオン
- [ ] VPCを作成し、パブリック/プライベートサブネットを切る
- [ ] パブリックサブネットにEC2を立て、SSH接続する
- [ ] セキュリティグループでアクセスを絞ってみる

### つまずきポイント
- 「繋がらない」の8割はSG/NACL/ルートテーブルのどれか。切り分けの順番を覚える
- NATゲートウェイは課金されるので、検証後は忘れず削除

> 💼 **現役エンジニアのひとこと**
> VPCは試験の最重要かつ実務の土台です。「パブリック/プライベートサブネットの違い」を**図を自分で描いて**説明できるようにすると、一気に得点源になります。現場では「DBはプライベート最奥、公開はALBだけ」が基本形です。

---

## 第3週：ストレージ & データベース

### この週で学ぶこと
- **S3**：ストレージクラス、ライフサイクル、バージョニング、バケットポリシー、静的ホスティング
- **EBS / EFS / インスタンスストア**の違い
- **RDS**：マルチAZ、リードレプリカ、バックアップ
- **DynamoDB**：NoSQLの基本と、RDBとの使い分け

### 今週のハンズオン
- [ ] S3バケットを作り、静的サイトを公開してみる
- [ ] ライフサイクルルールを設定してみる
- [ ] RDSインスタンスを起動し、接続する（検証後は停止/削除）

### つまずきポイント
- 「マルチAZ」と「リードレプリカ」の目的を混同しやすい（下の早見表で確認）
- S3の公開設定ミスは情報漏洩に直結。ブロックパブリックアクセスは原則ON

> 💼 **現役エンジニアのひとこと**
> 「マルチAZ＝可用性（落ちない）」「リードレプリカ＝読み取り性能（速く・たくさん読む）」。この**目的の違い**は頻出かつ混同しやすく、現場の設計でも必ず議論になります。

---

## 第4週：可用性・スケーラビリティ

### この週で学ぶこと
- **ELB**：ALB（L7）/ NLB（L4）の違いと使い分け
- **Auto Scaling**：スケーリングポリシー、ヘルスチェック
- **Route 53**：ルーティングポリシー、ヘルスチェック、フェイルオーバー
- **ステートレス設計**：なぜスケールアウトに必須か

### 今週のハンズオン
- [ ] ALB + Auto Scaling で複数AZの冗長構成を組む
- [ ] インスタンスを意図的に1台落として、自動復旧を観察する

### つまずきポイント
- ステートレスの意味が腹落ちしないと、Auto Scaling系の問題で迷う
- ヘルスチェックの設定値（しきい値・間隔）の意味を理解しておく

> 💼 **現役エンジニアのひとこと**
> 「ステートレス設計（サーバーに状態を持たせない）」がなぜ重要かを理解すると、Auto Scaling系の問題が一気に腹落ちします。セッション情報はElastiCacheやDBに逃がす——これは現場の必須設計思想です。

---

## 第5週：セキュリティ & 管理

### この週で学ぶこと
- **IAM**：ユーザー / グループ / ロール / ポリシー、最小権限の原則
- **KMS / Secrets Manager / Parameter Store**：暗号化と機密管理
- **CloudWatch**（メトリクス・アラーム・Logs）/ **CloudTrail**（監査ログ）

### 今週のハンズオン
- [ ] IAMロールを作成し、EC2に付与してS3へアクセスする
- [ ] CloudWatchアラームを設定し、通知を受け取る

### つまずきポイント
- IAMの「ユーザー」と「ロール」の使い分けが最初は分かりにくい
- アクセスキーをコードに書く癖をつけない（ロールで渡す）

> 💼 **現役エンジニアのひとこと**
> 「アクセスキーをコードに直書き」は現場では事故のもと。**IAMロールで権限を渡す**のが正解です。試験でもこの「ロールベース」の考え方が繰り返し問われます。迷ったら「最小権限」を思い出してください。

---

## 第6週：アーキテクチャ設計（点を線にする）

### この週で学ぶこと
- **Well-Architected Framework** の6本の柱
- **疎結合**：SQS / SNS / EventBridge の使い分け
- **サーバーレス**：Lambda / API Gateway / DynamoDB
- これまでの知識を「要件 → 最適な構成」で繋げる練習

### 今週のハンズオン
- [ ] Lambda + API Gateway で簡単なAPIを作る
- [ ] 学んだサービスを使って「小さなWebアプリ構成」を紙に設計してみる

### つまずきポイント
- ここでバラバラの知識が1枚の絵になるかが勝負
- 「どの柱を優先する問題か」を意識して設計を考える

> 💼 **現役エンジニアのひとこと**
> SAAは「サービスの暗記」ではなく「**要件に対して最適な組み合わせを選ぶ**」試験です。第6週で、バラバラだった知識が1枚の絵になります。ここが合否の分かれ目。

---

## 第7週：問題演習①（弱点をあぶり出す）

### この週でやること
- 模試・問題集を1〜2セット解く
- **間違えた問題を「なぜ間違えたか」までノート化**する
- 弱いカテゴリを第2〜6週の該当箇所に戻って復習

### 間違いの「3分類」（超重要）
| 分類 | 対策 |
|---|---|
| 知らなかった | 該当週に戻ってインプット |
| 読み間違えた | 問題文の読み方・キーワード抽出を訓練 |
| 迷って外した | 「AWSの思想」で判断する練習 |

> 💼 **現役エンジニアのひとこと**
> 点数に一喜一憂しないこと。大事なのは**「間違いの理由の分類」**です。同じ60点でも、3分類の内訳で次にやるべきことは全く変わります。

---

## 第8週：問題演習②＋総仕上げ

### この週でやること
- 模試をさらに2〜3セット、安定して**正答率80%以上**を確認
- 頻出サービスの「目的・違い」を早見表で最終チェック
- 試験前日は詰め込まず、コンディションを整える
- **受験！** 🎉

### 試験本番の戦術（当日効く）
- **消去法**：明らかに違う選択肢を先に2つ消す
- **キーワード抽出**：「最もコスト効率」「最小の運用」等の条件語に線を引く
- **時間配分**：迷ったらフラグを立てて先へ。全問一周してから戻る
- **見直し**：時間が余ったらフラグ問題を再検討

> 💼 **現役エンジニアのひとこと**
> 本番は「2択で迷う」問題が必ず出ます。そのとき効くのが「**コスト最適化**」「**マネージドサービス優先**」「**最小権限**」「**疎結合・冗長化**」という**AWSの思想**。迷ったら思想に立ち返ると正解率が上がります。

# 📎 付録（ここが本ガイドの差別化ポイント）

---

## 付録A：頻出サービス「目的の違い」早見表

混同しやすいペアを「目的」で整理。試験前の最終確認に。

| 比較 | A | B | 覚え方 |
|---|---|---|---|
| 可用性 vs 読み取り | **マルチAZ**=落ちない | **リードレプリカ**=たくさん読む | 「守る」か「速く読む」か |
| 範囲 | **マルチAZ**=地域内 | **マルチリージョン**=地域またぎ | 災害対応はリージョン |
| メッセージ | **SQS**=行列で後処理 | **SNS**=一斉通知 | 券売機 vs メルマガ |
| ファイアウォール | **SG**=インスタンス/ステートフル | **NACL**=サブネット/ステートレス | NACLは戻りも明示許可 |
| 機密管理 | **Parameter Store**=安い | **Secrets Manager**=自動ローテーション | ローテーションが要るか |
| ストレージ | **EBS**=単一・ブロック | **EFS**=共有・ファイル | 複数から使うならEFS |
| 攻撃対策 | **WAF**=アプリ層(L7) | **Shield**=DDoS | SQLi/XSSはWAF |

---

## 付録B：課金事故を防ぐ「最初の3つ」

AWSを触る前に必ず設定してください。事故ってからでは遅いです。

1. **AWS Budgets で予算アラート**（しきい値50% / 80% / 100%でメール通知）
2. **Cost Explorer を週1で確認する習慣**（何にいくらかかっているか体感する）
3. **無料利用枠の超過アラートをON**

> やりがちな課金事故TOP3：①NATゲートウェイ消し忘れ ②RDS/EC2の止め忘れ ③Elastic IPの未使用課金
