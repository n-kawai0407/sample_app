## はじめに：「L7だからALB」だけでは選べない

SAAでELBは「ALBはL7、NLBはL4」と暗記します。間違いではありません。
でも現場で「で、どっちを使う？」となったとき、暗記だけでは判断できない場面が多い。
実務の選定基準を整理します。

## まず基本：3種類のELB

| 種類 | レイヤー | 主な用途 |
|---|---|---|
| **ALB**（Application LB） | L7（HTTP/HTTPS） | Web/APIアプリの振り分け |
| **NLB**（Network LB） | L4（TCP/UDP） | 超高性能・低レイテンシ・固定IP |
| CLB（Classic LB） | L4/L7 | 旧世代。新規は非推奨 |

> 新規はALBかNLBの二択。CLBは既存システムでしか見ません。

## ALBの強み（L7だからできること）

- **パスベースルーティング**：`/api` はサーバーA、`/img` はサーバーB
- **ホストベースルーティング**：ドメインごとに振り分け
- **HTTPヘッダ/メソッドでの振り分け**
- **WAF連携**：アプリ層の攻撃をブロック
- コンテナ（ECS）との相性が良い

→ **Web・API・マイクロサービスの振り分け**ならALBが基本。

## NLBの強み（L4だからできること）

- **超高スループット・超低レイテンシ**（数百万リクエスト/秒）
- **静的IP / Elastic IP を付与できる**（IP固定が要件のとき決定的）
- **TCP/UDP**に対応（HTTPでないプロトコル）
- ソースIPを保持できる

→ **極端な性能要件、IP固定要件、非HTTPプロトコル**ならNLB。

## 現場の選定フロー

```
Q1. HTTP/HTTPSのWeb/APIで、パスやホストで振り分けたい？
    └─ YES → ALB

Q2. 固定IPが必要 / 非HTTP(TCP・UDP) / 極端な高性能・低レイテンシ？
    └─ YES → NLB

Q3. 両方の要件がある？
    └─ NLB の後ろに ALB を置く構成もある（IP固定＋L7振り分け）
```

## よくある選定理由（実務あるある）

- 「ファイアウォールの許可をIPでしたい」と顧客に言われ**NLBで固定IP**
- 「1つのLBで複数サービスを `/path` で振り分けたい」→ **ALB**
- 「ゲームサーバーでUDP」→ **NLB**
- 「とにかく速く、LB自体をボトルネックにしたくない」→ **NLB**

## SAAでの問われ方

- 「パス/ホストでルーティング」「HTTPヘッダで」→ **ALB**
- 「静的IPが必要」「TCP/UDP」「極めて高いスループット」→ **NLB**

キーワードで反射的に選べると得点源になります。

## まとめ

- 暗記の「L7=ALB / L4=NLB」は出発点にすぎない
- **振り分けの賢さが欲しい→ALB**、**性能・固定IP・非HTTP→NLB**
- 現場では「要件の言葉」から逆算して選ぶ

「なぜそれを選ぶか」を語れると、面接でも現場でも一目置かれます。
