## はじめに：AWSの怖さは「気づいたときには遅い」こと

クラウドの便利さの裏側に、**「使った分だけ課金される」**という現実があります。
学習目的でちょっと触っただけのつもりが、月末に予想外の請求 ── これは合格者でも、現役エンジニアでもやらかします。

この記事では、**よくある課金事故TOP5**と、その**確実な防ぎ方**をまとめます。これからAWSを学ぶ人は、手を動かす前に必ず読んでください。

課金事故の本質は、**「作ったものが、見えないところで動き続けている」**ことです。コンソールのトップ画面には出てこないリソース（解放し忘れたEIP、別リージョンに立てたまま忘れたインスタンス、消したEC2に残ったEBS）が、静かに時間課金を積み上げます。だからこそ「作ったものを把握する仕組み」と「異常に気づく仕組み」を最初に作るのが、何よりの防御になります。

> 💡 特に注意したいのが**リージョンの取り違え**。普段使うリージョンと違う場所にうっかりリソースを立てると、コンソールのリージョンを切り替えるまで存在に気づけません。「身に覚えのない課金」の定番原因です。

## 事故TOP5（あるある順）

### ① NATゲートウェイの消し忘れ
作ったまま放置すると、**何もしなくても時間課金**され続けます。検証でVPCを作ると一緒に立てがち。NATゲートウェイは「起動している時間」と「通したデータ量」の両方で課金されるため、放置の代償が地味に大きいリソースの代表格です。
→ **対策**：検証後は必ず削除。通信先がS3/DynamoDBなら**ゲートウェイ型VPCエンドポイント**で代替でき、しかもこの型は追加料金がかからないのが定番（最新の料金体系は公式で要確認）。

```bash
# 自分のアカウントに生きているNATゲートウェイを洗い出す
aws ec2 describe-nat-gateways \
  --filter "Name=state,Values=available" \
  --query "NatGateways[].{Id:NatGatewayId,Subnet:SubnetId}" \
  --output table
```

### ② Elastic IPの「未使用」課金
EIPは**インスタンスに紐づいていないと課金**されます。「確保したけど使ってない」が罠。停止中のインスタンスに付けっぱなしのEIPも課金対象になりがちです。
→ **対策**：使わないEIPは解放（Release）する。

```bash
# どのEIPがどのインスタンスに紐づいているか確認（Associationが空＝未使用の疑い）
aws ec2 describe-addresses \
  --query "Addresses[].{IP:PublicIp,Instance:InstanceId,AllocId:AllocationId}" \
  --output table
```

### ③ EBS・スナップショットの残骸
EC2を消してもEBSボリュームやスナップショットが残り、ストレージ課金が続くことがあります。インスタンス作成時に「終了時に削除（DeleteOnTermination）」が無効だと、ボリュームだけ生き残ります。
→ **対策**：インスタンス削除時にボリュームも削除。不要なスナップショットは整理。

```bash
# どこにもアタッチされていない（available）EBSボリュームを洗い出す
aws ec2 describe-volumes \
  --filters "Name=status,Values=available" \
  --query "Volumes[].{Id:VolumeId,Size:Size,AZ:AvailabilityZone}" \
  --output table
```

### ④ 止め忘れたRDS・EC2
検証用のDBやサーバーを起動しっぱなし。RDSは特に高くつきます。RDSは**停止しても数日で自動的に再起動する**仕様があるため、「止めたから安心」と思っていると課金が復活していることがあります（挙動・期間は変わりうるので公式で要確認）。
→ **対策**：使わない時間帯は停止。長く使わないなら**スナップショットを取って削除**。検証環境は夜間・休日に自動停止する仕組み（EventBridge + Lambda など）を入れる。

### ⑤ S3への大量リクエスト/転送
ストレージ代より、**リクエスト数やデータ転送（特にインターネットへの外向き）**で積み上がることも。AWSは原則「外向き（アウトバウンド）転送」に課金され、受信は無料なことが多い、という非対称があります（最新は公式で要確認）。公開バケットに大量アクセスが来ると、転送料で一気に跳ねます。
→ **対策**：不要な公開を避ける、CloudFront等でキャッシュして転送を抑える、意図しない公開がないか定期点検。

### 番外：意外と多い「その他」
- **無料利用枠の期間切れ**：12ヶ月の無料枠が切れた途端に通常課金へ（期間・対象は変動、公式で要確認）
- **CloudWatch の詳細メトリクス/ログ保管**：ログを無期限保管していると地味に積む
- **試したマネージドサービスの放置**：OpenSearch、ElastiCache、Redshift など「立てると高い」系の消し忘れ

## 最初にやるべき「3つの防御」

事故ってからでは遅い。アカウントを作ったら、**真っ先に**これを設定してください。

1. **AWS Budgets で予算アラート**
   月の予算を決め、しきい値（例：50%・80%・100%）でメール通知。
2. **Cost Explorer を週1で見る習慣**
   「何にいくらかかっているか」を体で覚える。異常にすぐ気づける。
3. **無料利用枠の超過アラート**
   Free Tierの上限に近づいたら通知してくれる設定をON。

### 手順：予算アラートの設定（ステップ分解）

1. ルートではなく**管理用のIAMユーザー**でサインイン（ルートは普段使わない）
2. 請求情報へのアクセスをIAMユーザーに許可（ルートでの初回設定が必要な場合あり）
3. **Billing and Cost Management → Budgets → 予算を作成**
4. タイプは「コスト予算」、金額（例：月 10 USD など低めの安全弁）を設定
5. アラートのしきい値を **50% / 80% / 100%** で複数設定
6. 通知先メールを設定（SNSトピック経由でSlack等にも飛ばせる）
7. 保存し、テスト的にしきい値を低くして通知が届くか確認

> 💼 現場でも、新しいアカウントを払い出したらまずやるのが予算アラート設定です。「コスト管理は最初の一手」が鉄則。

### おすすめのガードレール（少し進んだ防御）

- **MFAを全ユーザーに必須化**：不正利用による課金事故（マイニング等）の予防
- **使わないリージョンを制限**：意図しないリージョンへのリソース作成をSCP等で禁止（組織を使っている場合）
- **タグ運用**：`Project` `Owner` `Env` などのタグを付け、Cost Explorerでタグ別に集計できるようにする
- **定期的な棚卸し**：上のCLIコマンドで「未使用EIP / available EBS / 生きているNAT」を月1で点検

## 想定FAQ

**Q. 無料利用枠の中なら絶対に課金されない？**
A. いいえ。無料枠には**対象サービス・上限・期間**があり、それを超えた分や対象外の操作は課金されます。上限・期間は変動するので、**必ず公式の無料利用枠ページで最新を確認**してください。

**Q. リソースを全部消したのに課金が止まりません。**
A. 別リージョンに残っていないか、スナップショット/EBS/EIP/Route 53 ホストゾーンなどの「コンソールトップに出にくいもの」が残っていないかを確認してください。Cost Explorerで「どのサービスが課金しているか」を見るのが最短です。

**Q. 予算アラートは課金を止めてくれますか？**
A. いいえ。Budgetsは**通知する**だけで、自動で止めはしません（アクション設定で一部自動対応は可能だが万能ではない）。「気づくための仕組み」と割り切り、気づいたら自分で止めるのが基本です。

**Q. 高額請求が来たら絶対に減免される？**
A. 保証はありません。下の項を参照してください。

## もし高額請求が来てしまったら

1. まずは落ち着いて **Cost Explorer / 請求ダッシュボード**で原因サービス・リージョンを特定
2. 原因リソースを**停止・削除**して出血を止める（まずこれ）
3. 不正利用（アクセスキー流出によるマイニング等）が疑われるなら、**該当キーの無効化・ローテーション**とパスワード変更、MFA有効化
4. 学習中の予期せぬ高額請求は、**サポートに状況を説明すると一度は減免されるケースもある**（あくまでケースバイケース、保証はされません）
5. 二度と繰り返さないよう、予算アラートとガードレールを必ず入れる

## まとめ

- AWSは「使った分だけ課金」。消し忘れ・止め忘れが事故の主因
- **NATゲートウェイ / EIP / EBS / 起動しっぱなし / 転送量**に注意。リージョン取り違えも定番
- **アカウント作成直後に予算アラート＋Cost Explorer習慣**で大半は防げる
- 料金・無料枠・クォータは変動する。**金額は目安、最新は必ず公式で確認**
