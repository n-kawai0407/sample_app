## はじめに：AWSの請求書、9割の現場に「無駄」がある

クラウドは「使った分だけ」が魅力。でも裏を返せば、**気づかぬうちに無駄が積み上がる**のもクラウド。
現場でコストを見直すと、ほぼ必ず削れる箇所が出てきます。今日は**削れる無駄ベスト10**を、効果の大きい順に紹介します。

## 削れる無駄ベスト10

### 1位：使っていないリソースの放置
止め忘れのEC2/RDS、未使用のEIP、孤立したEBSボリュームやスナップショット。
→ **対策**：定期的に棚卸し。Trusted Advisorやコスト異常検出で洗い出す。

### 2位：オーバースペックなインスタンス
「念のため大きめ」で立てたまま。CPU/メモリがガラガラ。
→ **対策**：Compute Optimizerの推奨を見てライトサイジング。

### 3位：購入オプションの未最適化
常時稼働なのにオンデマンドのまま。
→ **対策**：定常稼働分はSavings Plans / リザーブドインスタンスでコミット割引（最大数割引）。

### 4位：検証環境の24時間稼働
夜間・休日も開発環境が動きっぱなし。
→ **対策**：スケジュールで自動停止。使う時間だけ起動。

### 5位：S3のストレージクラス未最適化
アクセスされない古いデータがStandardのまま。
→ **対策**：ライフサイクルルールでIA/Glacierへ自動移行。読めないならIntelligent-Tiering。

### 6位：NATゲートウェイの無駄
複数AZに過剰配置、またはS3/DynamoDBアクセスもNAT経由。
→ **対策**：S3/DynamoDBはVPCエンドポイントで迂回。検証はNAT 1つに集約。

### 7位：データ転送料の見落とし
特にインターネットへの外向き転送、AZ/リージョンまたぎの通信。
→ **対策**：CloudFrontでキャッシュ、通信経路を見直す。

### 8位：ログの貯めすぎ
CloudWatch Logsを無期限保持。S3に大量の不要ログ。
→ **対策**：保持期間を設定。古いログはS3/Glacierへ、不要は削除。

### 9位：取りっぱなしのスナップショット/AMI
世代管理されず延々と溜まる。
→ **対策**：ライフサイクルマネージャーで世代数を制限。

### 10位：開発者ごとの「野良リソース」
誰のものか分からないリソースが散在。
→ **対策**：タグ付けを徹底し、コスト配分タグで可視化。

## コスト最適化の「仕組み化」

単発の掃除でなく、続く仕組みにするのが現場の知恵。

1. **タグ戦略**：プロジェクト/環境/オーナーをタグ付け → Cost Explorerで内訳が見える
2. **予算アラート**：Budgetsでしきい値通知
3. **コスト異常検出**：いつもと違う請求を自動検知
4. **定期レビュー**：月1でCost Explorerを眺める習慣

## SAAでの効き方

「最もコスト効率が良いのは？」という問題は頻出。判断軸は：
- 常時稼働 → コミット割引（Savings Plans/RI）
- 中断OK → スポット
- アクセス頻度で → S3ストレージクラス/ライフサイクル
- マネージド/サーバーレスで運用コストも下げる

## まとめ

- AWSのコストは**ほぼ必ず削れる**。まずは棚卸しとライトサイジング
- 常時稼働はコミット割引、検証は自動停止が効果大
- 単発でなく**タグ＋予算アラート＋定期レビュー**で仕組み化

コスト感覚は、現場で最も評価されるスキルの一つ。資格勉強の段階から意識すると一歩リードできます。
