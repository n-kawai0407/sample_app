## 結論：SAAは「暗記」ではなく「設計の判断」を問う試験

最初に結論から。SAA（AWS Certified Solutions Architect – Associate）に最短で受かるコツは、

**「サービス名を暗記する」のをやめて、「要件→最適な構成を選ぶ」練習をする**

ことです。私自身、現役のエンジニアとして実務でAWSを触りながら学び直したとき、これが一番の近道だと確信しました。この記事では、働きながら**2ヶ月（週6〜8時間）**で合格するロードマップを、現場の視点を交えて具体的に示します。

SAAの問題文は、たいてい「ある会社が〜という要件で〜したい。最も適切な構成はどれか？」という形をしています。つまり問われているのは「サービスを知っているか」ではなく、**「複数の正しそうな選択肢から、要件に最も合うものを選べるか」**です。たとえば4択すべてが技術的には動く構成で、そのうち「最もコスト効率が良い」「最も可用性が高い」「最も運用負荷が低い」ものを選ばせる──そういう問い方が中心になります。だから丸暗記では太刀打ちできず、逆に「判断軸」を身につけた人は初見の問題でも安定して解けるようになります。

> 💡 試験の傾向として、近年は「単一サービスの仕様を問う」問題より「複数サービスを組み合わせた構成の良し悪しを問う」問題のほうが目立ちます（出題内容は改定されるため、申込時に最新の試験ガイドで範囲を確認してください）。

## 前提：あなたはどのタイプ？

| タイプ | 想定期間 | 補足 |
|---|---|---|
| IT実務経験あり | 約2ヶ月 | この記事の標準プラン |
| IT基礎はある（インフラ未経験） | 2〜3ヶ月 | ハンズオンを厚めに |
| 完全未経験 | 3〜4ヶ月 | まずCLFから推奨 |

「自分がどのタイプか」で最適なペースは変わります。特に**ネットワーク（VPC・ルーティング・サブネット）の前提知識があるか**で序盤のスピードが大きく変わるので、ここが弱い人は第1〜2週を厚めに取ってください。

### 受験の前提情報（目安・最新は公式で要確認）

| 項目 | 目安 |
|---|---|
| 試験コード | SAA-C03 系（改定されるため公式で要確認） |
| 問題数 | 65問程度 |
| 試験時間 | 130分程度 |
| 合格スコア | 720 / 1000 が目安 |
| 受験形式 | テストセンター or オンライン監督付き |
| 有効期限 | 3年（再認定が必要） |

※ 受験料・問題数・合格ラインは改定されることがあります。**申込画面と公式の試験ガイドで必ず最新を確認**してください。

## 教材の黄金比率

あれこれ手を出すと挫折します。最小構成はこれだけ。

1. **参考書 or 動画講座 × 1**（全体像のインプット用）
2. **問題集・模試 × 1〜2**（アウトプット用、これが本体）
3. **AWS無料利用枠でのハンズオン**（理解を定着させる）

比率の目安は **インプット3 : 問題演習5 : ハンズオン2**。多くの人はインプットに偏りすぎて落ちます。**問題演習が主役**です。

### 教材選びのチェックリスト

- [ ] 参考書は「最新の試験コードに対応」と明記されているか
- [ ] 問題集は**解説が丁寧**か（答えだけでなく「なぜ他の選択肢がダメか」まで書いてあるか）
- [ ] 模試が**本番に近い形式・問題数**で受けられるか
- [ ] 動画講座を選ぶなら、ハンズオンが含まれているか

> 💡 「参考書を2冊買って読み比べる」は典型的な遠回り。1冊を浅く2周し、残りの時間を全部問題演習に回したほうが、合格率は上がります。

## 8週間ロードマップ

全体像はこうです。**前半でサービスを面で押さえ、後半で点と点を線で結ぶ（＝設計）**のがポイント。

```
週: 1   2   3   4   5   6   7   8
   [土台]   [データ/スケール] [セキュリティ/設計] [演習/仕上げ]
   VPC      S3/RDS/Dynamo     IAM/KMS/監視        模試×反復
   EC2      ELB/ASG/Route53   Well-Architected    弱点潰し
```

### 第1〜2週：土台（全体像＋ネットワーク）
- AWSの主要カテゴリを俯瞰し、**まず予算アラートを設定**
- VPC / EC2 を理解し、実際にVPC内にEC2を立ててSSH接続

具体的なハンズオンの最小ゴールはこれです。

1. VPC（`/16`程度）を作り、パブリック/プライベートのサブネットを切る
2. インターネットゲートウェイ（IGW）をアタッチし、パブリックサブネットのルートテーブルに `0.0.0.0/0 → igw` を足す
3. パブリックサブネットにEC2（無料利用枠対象のインスタンスタイプ）を立て、SSHで入る
4. 検証が終わったら**必ずEC2を停止/削除**（課金事故防止）

CLIで挙動を確認するなら、たとえば自分のVPC一覧はこう取れます。

```bash
# VPCの一覧を確認
aws ec2 describe-vpcs --query "Vpcs[].{Id:VpcId,CIDR:CidrBlock}" --output table

# サブネットとAZの対応を確認
aws ec2 describe-subnets \
  --query "Subnets[].{Subnet:SubnetId,AZ:AvailabilityZone,CIDR:CidrBlock}" \
  --output table
```

> 💡 VPCは試験の最重要かつ実務の土台。「パブリック/プライベートサブネットの違い」を自分で図に描けるようにすると一気に得点源になります。

### 第3〜4週：データとスケール
- S3 / EBS / RDS / DynamoDB のストレージ・DB群
- ELB / Auto Scaling / Route 53 の可用性・スケール群

この時期に押さえたい「目的の違い」を表にしておきます。混同しやすいところは表で整理すると記憶に残ります。

| 比較 | 何が違うか | 一言で |
|---|---|---|
| S3 vs EBS vs EFS | オブジェクト / ブロック / 共有ファイル | 用途で選ぶ |
| RDS マルチAZ vs リードレプリカ | 可用性 vs 読み取りスケール | 目的が違う |
| RDS vs DynamoDB | リレーショナル vs キーバリュー(NoSQL) | クエリ要件で選ぶ |
| ELB(ALB) vs Route 53 | L7ロードバランス vs DNSルーティング | 層が違う |
| Auto Scaling vs マルチAZ | 台数を増減 vs 別AZに待機 | スケール vs 可用性 |

ハンズオンの一例として、S3のライフサイクルやバージョニングはCLIで体験すると腹落ちします。

```bash
# バケットにバージョニングを有効化（料金は発生しうるので検証後に整理）
aws s3api put-bucket-versioning \
  --bucket your-unique-bucket-name \
  --versioning-configuration Status=Enabled
```

> 💡 「マルチAZ＝可用性」「リードレプリカ＝読み取りスケール」。この目的の違いは頻出かつ混同しやすい。ここを押さえると正答率が跳ねます。

### 第5〜6週：セキュリティと設計
- IAM / KMS / 監視（CloudWatch・CloudTrail）
- Well-Architected で、バラバラの知識を「設計」として繋げる

IAMは「ユーザー/グループ/ロール/ポリシー」の関係を図で描けるかが勝負。特に**ロール（一時的な権限の引き受け）**は試験でも実務でも最重要です。「EC2やLambdaに権限を渡すときはアクセスキーを埋め込まず、ロールを使う」という原則を体に入れてください。

最小権限の感覚をつかむため、IAMポリシーの形を一度は自分で読んでおきましょう。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject"],
      "Resource": "arn:aws:s3:::example-bucket/*"
    }
  ]
}
```

監視の3点セットも目的で区別します。

| サービス | 役割 | 一言 |
|---|---|---|
| CloudWatch | メトリクス/ログ/アラーム | 「今どうなっているか」を見る |
| CloudTrail | API呼び出しの記録（監査ログ） | 「誰が何をしたか」を追う |
| AWS Config | 構成変更の記録/評価 | 「設定が基準に沿っているか」を見る |

> 💡 SAAは「サービス暗記」でなく「組み合わせの選択」を問う試験。第6週でようやく知識が1枚の絵になります。ここが合否の分かれ目。

### 第7〜8週：演習と仕上げ
- 模試を繰り返し、**安定して80%以上**を確認
- 間違いは「知らなかった/読み違えた/迷って外した」に**分類して対策**
- 受験！

間違いの分類は、対策の打ち手がそれぞれ違うので必ず分けてください。

| 間違いの種類 | 原因 | 打ち手 |
|---|---|---|
| 知らなかった | 知識の穴 | 該当サービスをハンズオン+再インプット |
| 読み違えた | 設問の見落とし | キーワード（最もコスト/最も可用性 等）に線を引く癖をつける |
| 迷って外した | 判断軸が曖昧 | 後述の「AWSの思想」で2択を切る練習 |

## 落ちる人がやりがちな3つの罠

1. **インプット沼**：参考書を完璧にしようとして問題演習が手薄に → 演習を主役に
2. **過去問の丸暗記**：答えを覚えるだけ → 「なぜその答えか」を説明できるか確認
3. **ハンズオンゼロ**：手を動かさず用語が腹落ちしない → 1サービス1ハンズオン

### Before / After：私が見てきた典型例

**Before（落ちる人）**：参考書を3周してマーカーだらけ。でも模試を受けると60%台。「知っているはずなのに選べない」と悩む。

**After（受かる人）**：参考書は2周で切り上げ、4週目から毎日模試の復習。「なぜこの選択肢が×なのか」を声に出して説明できるようにした。模試が安定して80%を超えた状態で受験し、一発合格。

差は知識量ではなく、**アウトプットの量と、間違いの分析の深さ**でした。

## 迷ったときの「AWSの思想」

本番では2択で迷う問題が必ず出ます。そのとき効くのが次の判断軸。

- **コスト最適化**（使う時だけ・安いほうへ）
- **マネージドサービス優先**（自前運用を避ける）
- **最小権限**（必要な権限だけ与える）
- **疎結合・冗長化**（直結を避け、複数AZへ）

迷ったらこの思想に立ち返ると、正解率が上がります。

具体的には、こんな対応関係を覚えておくと2択を切りやすくなります。

| 設問のキーワード | 寄せるべき答えの方向 |
|---|---|
| 「運用負荷を下げたい」「管理したくない」 | マネージドサービス（RDS、Fargate、Lambda 等） |
| 「コストを最小に」 | 使った分だけ・サーバーレス・適切なストレージクラス |
| 「可用性を高めたい」 | 複数AZ、マルチAZ、Auto Scaling |
| 「疎結合に」「スパイクを吸収」 | SQS / SNS などのメッセージング |
| 「最小権限で」「安全に権限を渡す」 | IAMロール（アクセスキー直書きは避ける） |

> 💡 4択のうち2つは「明らかに方向性が違う」ことが多いです。まずその2つを切り、残り2つを上の表で判定する──これだけで体感の正答率がかなり上がります。

## 想定FAQ

**Q. 参考書は最新版でないとダメ？**
A. 試験コードに対応していれば多少前の版でも本質は変わりませんが、新サービスが範囲に入ることがあるので、**問題集・模試は最新のもの**を選ぶのが無難です。

**Q. ハンズオンで課金が怖いです。**
A. アカウント作成直後に予算アラートを設定し、検証後はリソースを必ず削除すれば大半は防げます（別記事「やらかしがちなAWS課金事故」も参照）。無料利用枠の範囲・上限は変動するので、**最新を公式で確認**してください。

**Q. CLFを飛ばしてSAAから受けていい？**
A. IT実務経験があれば直接SAAで問題ありません。完全未経験ならCLFで全体像をつかむと、SAAの学習がスムーズになります。

**Q. 模試で何%取れたら受けていい？**
A. **複数回・別の模試で安定して80%以上**が目安。1回だけ高得点でも、ヤマが当たっただけのことがあります。

**Q. オンライン受験とテストセンター、どっち？**
A. 静かで安定したネット環境・カメラ・身分証が用意できるならオンラインも便利。ただし環境チェックが厳しいので、不安ならテストセンターが確実です。

- [ ] アカウント作成直後に予算アラートを設定した

- [ ] IAMのユーザー/グループ/ロール/ポリシーの関係を図で描ける
- [ ] Well-Architectedの観点で構成の良し悪しを語れる
- [ ] 模試が複数回・安定して80%以上
- [ ] 間違いを3分類して対策した
