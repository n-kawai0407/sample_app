## なぜAWS資格は「丸暗記」だと落ちるのか

AWSのサービスは200以上。これを名前と説明で丸暗記しようとすると、

- 似たサービスが混ざる（SQSとSNS、StandardとStandard-IA…）
- シナリオ問題で「どれが最適か」を選べない
- 覚えても3日で忘れる

SAAをはじめAWS資格は **「知っているか」ではなく「使い分けられるか」** を問います。だから暗記は相性が悪いのです。

もう少し踏み込むと、人間の記憶は「意味のつながり」がないとすぐ抜け落ちます。「SQS＝フルマネージドのメッセージキューイングサービス」という文字列は、あなたの頭の中で**他のどんな知識ともつながっていない**ので、覚えたそばから忘れます。逆に「SQS＝ラーメン屋の券売機」のように**すでに知っている場面に結びつける**と、思い出すフックが増え、忘れにくくなります。これは記憶研究でいう「精緻化（elaboration）」に近い考え方で、丸暗記より圧倒的に定着します。

### 丸暗記が崩れる典型シーン

試験本番でこういう問題が出ます。

> ある企業が、注文処理のピーク時にバックエンドが過負荷で落ちる問題を抱えている。注文を取りこぼさず、バックエンドを保護しつつ非同期で処理したい。最適なのはどれか？

丸暗記の人は「SQS＝メッセージキュー」とは言えても、「過負荷を吸収する」「取りこぼさない」というキーワードとSQSが結びつかず、SNSやKinesisと迷って外します。**用語の定義ではなく"目的"を絵で持っている人**だけが、迷わず選べます。

## 解決策：用語を「現場の一場面」に変換する

私が現役エンジニアとして実感したのは、**用語を"動き"のある絵で覚える**と忘れないということ。例を挙げます。

### 例1：SQS（キュー）

❌ 暗記：「SQSはフルマネージドのメッセージキューイングサービス」

⭕ 絵で覚える：**ラーメン屋の券売機**。お客（リクエスト）が殺到しても、まず食券（メッセージ）を買って並ぶ。店員（バックエンド）は自分のペースで順番に作る。だから厨房がパンクしない。＝**負荷の平準化・疎結合**。

この絵があると、関連する細かい仕様も自然に腹落ちします。

- **食券は作り終わるまで消えない**＝コンシューマが処理して明示的に削除するまでメッセージは残る（処理中は他から見えなくなる＝可視性タイムアウト）
- **食券には期限がある**＝メッセージには保持期間があり、目安として最大14日程度（最新は公式で要確認）
- **同じ食券で二度作っちゃうことがある**＝標準キューは「最低1回（at-least-once）」配信なので、受け取り側は重複に備える（冪等に作る）

### 例2：リードレプリカ vs マルチAZ

❌ 暗記：両方「DBの冗長化」

⭕ 絵で覚える：
- **マルチAZ** = 控えの選手（スタンバイ）。レギュラーが怪我（障害）したら即交代。**目的は試合を止めないこと＝可用性**。控えは普段は試合に出ない。
- **リードレプリカ** = コピー本を何冊も配って、みんなで同時に読む。**目的はたくさん読めること＝読み取りスケール**。

この「目的の違い」が絵になると、もう混ざりません。さらに表で並べると一発で区別がつきます。

| 観点 | マルチAZ | リードレプリカ |
|---|---|---|
| 目的 | 可用性（障害時の切り替え） | 読み取りスケール |
| 普段使うか | 待機（基本は使わない） | 読み取りに使う |
| 同期 | 同期レプリケーション | 非同期（遅延しうる） |
| 書き込み | できない（フェイルオーバー先） | できない（読み取り専用） |
| 別リージョン | 基本は同一リージョン | クロスリージョンも可 |

> 💡 「可用性が欲しい」ならマルチAZ、「読み取りが重い」ならリードレプリカ。両方欲しければ**両方使う**。これも丸暗記でなく「目的で選ぶ」発想です。

### 例3：S3ストレージクラス

❌ 暗記：Standard / IA / Glacier / Deep Archive…

⭕ 絵で覚える：**自宅の収納**。
- よく使う物 = 机の上（**Standard**、すぐ取れるが場所代高い）
- たまに使う物 = クローゼット（**Standard-IA**、安いがちょっと手間）
- 滅多に使わない物 = 屋根裏（**Glacier**、取り出しに時間）
- ほぼ開けない思い出の箱 = トランクルーム（**Deep Archive**、最安・最も時間）

ポイントは「**保管は安いほど、取り出しは高く・遅くなる**」というトレードオフ。アクセス頻度が読めないなら、自動で最適なクラスに移してくれる **S3 Intelligent-Tiering** という選択肢もあります（「どこに片付けるか自動で判断してくれる収納サービス」のイメージ）。

ライフサイクルルールで「30日経ったらIAへ、90日経ったらGlacierへ」と自動で移すのも定番です。設定の形を一度見ておくと、試験でも実務でもイメージが湧きます。

```json
{
  "Rules": [
    {
      "ID": "archive-old-logs",
      "Filter": { "Prefix": "logs/" },
      "Status": "Enabled",
      "Transitions": [
        { "Days": 30, "StorageClass": "STANDARD_IA" },
        { "Days": 90, "StorageClass": "GLACIER" }
      ]
    }
  ]
}
```

### 例4：IAMロール（おまけ）

❌ 暗記：「一時的な認証情報を引き受ける仕組み」

⭕ 絵で覚える：**職場の入館パス**。社員（IAMユーザー）は自分のIDを持つが、来客対応のときだけ「来客フロア用パス（ロール）」を借りて使い、用が済めば返す。**鍵を持ち歩く（アクセスキー直書き）のではなく、必要なときだけパスを借りる**＝安全。EC2やLambdaに権限を渡すときも、この「パスを借りる」方式を使うのが鉄則です。

## 「絵」を作るときのコツ

良い例えには共通点があります。自分で例えを作るときの指針にしてください。

- **動きがある**：静止画でなく「殺到する→並ぶ→順に捌く」のように時間で動く
- **すでに知っている場面**：知らない題材で例えても二度手間
- **目的が一言で出る**：例えから「＝負荷の平準化」のように目的が落ちてくる

逆に、**正確さを犠牲にしすぎる例え**は危険です。例えはあくまで「思い出すフック」。本番前には、例えに紐づけた**正確な仕様（数値・例外）**を一度確認しておきましょう。

## 暗記を「理解」に変える3ステップ

1. **目的を一言で言う**：「このサービスは"何のため"にあるのか」を1文で
2. **身近な例えに変換**：日常の場面に置き換える（上記のように）
3. **手を動かす**：無料利用枠で1回触る。「絵」が「体験」になり定着する

### 手を動かす最小ハンズオン例

各サービス、「1回だけ触る」ならこのくらいで十分です（**検証後は必ず削除**し、無料利用枠の範囲・上限は公式で要確認）。

| サービス | 最小ハンズオン |
|---|---|
| S3 | バケットを作り、ファイルを置いてライフサイクルを設定 |
| SQS | キューを作り、メッセージを送って受信・削除する |
| RDS | マルチAZを有効にして作成し、フェイルオーバーの挙動を眺める |
| IAM | 最小権限のポリシーを書いてロールに付け、EC2から使う |

```bash
# SQSの最小体験：キュー作成 → 送信 → 受信
aws sqs create-queue --queue-name demo-queue
aws sqs send-message --queue-url <QueueUrl> --message-body "hello"
aws sqs receive-message --queue-url <QueueUrl>
```

## やってはいけない勉強法

- ❌ 問題と答えのペアを丸暗記（少し問われ方が変わると崩れる）
- ❌ 参考書を1ページ目から完璧に読む（全体像→詳細の順が効率的）
- ❌ ハンズオンを飛ばす（用語が「自分の言葉」にならない）
- ❌ 例えを作って満足する（最後に正確な仕様で答え合わせをしないと、本番でズレる）

## 想定FAQ

**Q. 例えが思いつきません。**
A. まず「このサービスの目的を一言で」を埋めてください。目的さえ言葉になれば、例えは後から付きます。「目的＝負荷の平準化」→「並んで順に捌くもの＝行列・券売機」のように。

**Q. 例えだけで本番は大丈夫？**
A. 例えは思い出すためのフックです。本番直前には、各サービスの**正確な仕様（同期/非同期、上限の目安、例外）**を一度確認してください。例えと正確な知識はセットです。

**Q. 似たサービスをまとめて整理したい。**
A. 「目的」で表にするのが一番です（本文のマルチAZ vs リードレプリカ表のように）。定義でなく目的で並べると、混同が消えます。

## まとめ

AWS資格は暗記ゲームではなく「使い分け」のゲーム。

- 用語は **目的 → 身近な例え → 手を動かす** で「絵」にする
- 「なぜそれが最適か」を説明できれば、初見の問題でも解ける
- 例えは思い出すフック。最後は**正確な仕様で答え合わせ**

暗記で何度も挫折した人ほど、この方法は効きます。
