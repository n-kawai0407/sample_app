## はじめに：最初の一歩で多くの人が迷う

「AWSの資格を取ろう」と思い立った人が最初にぶつかる疑問。

- **CLF（クラウドプラクティショナー）とSAA、どっちから受ける？**
- **それぞれ何時間くらいで受かる？**

ネットには色々な意見があって迷いますよね。「CLFは不要、いきなりSAAでいい」という強気な意見もあれば、「CLFで足場を固めるべき」という慎重派もいる。どちらも一理あるのですが、**正解は人によって変わる**というのが実際のところです。

現役エンジニアとして、採用面接で何人もの候補者を見てきた立場から、**タイプ別のおすすめ**をはっきり示します。さらに「学習時間の目安」「使う教材」「つまずきポイント」まで踏み込んで解説します。

## まず2つの資格の違い

| | CLF（Cloud Practitioner） | SAA（Solutions Architect Associate） |
|---|---|---|
| 正式名称 | Certified Cloud Practitioner | Solutions Architect – Associate |
| レベル | 入門（Foundational） | アソシエイト（実務寄り） |
| 内容 | クラウドの概念・主要サービス・料金・セキュリティの責任共有 | サービスの使い分け・可用性/コスト/セキュリティを意識した設計 |
| 問われ方 | 「これは何のサービス？」が中心 | 「この要件ならどれを選ぶ？」が中心 |
| 難易度 | やさしい | 中程度 |
| 有効期限 | 3年（再認定が必要） | 3年（再認定が必要） |
| 市場価値 | 入門の証明 | **転職で評価されやすい** |

※受験料・出題範囲・有効期限などの条件は変わることがあります。**最新は必ずAWS公式（AWS Certification）で確認してください**。

### CLFとSAAの「問われ方」の違いを具体例で

同じ「S3」というサービスでも、聞かれ方がまるで違います。

- **CLFの典型**：「オブジェクトストレージサービスはどれか？」→ S3を選べればOK。サービスの正体を知っているかが問われる。
- **SAAの典型**：「アクセス頻度が低く、年に数回しか参照しないログを最も低コストで長期保存したい。どのストレージクラスが適切か？」→ S3 Glacier系を選ぶ、といった**要件から逆算した選択**が問われる。

この差が「CLFはやさしい、SAAは中程度」の正体です。CLFは暗記でかなり戦えますが、SAAは「なぜそれを選ぶのか」を理解していないと、似た選択肢に惑わされます。

## 結論：タイプ別おすすめ

### 完全未経験・IT初心者 → **CLFから**

いきなりSAAは挫折しやすい。CLFで**全体像と用語に慣れてから**SAAへ進むと、結果的に近道。
「リージョン」「アベイラビリティゾーン」「IAM」「責任共有モデル」といった基礎用語に先に慣れておくと、SAAの学習で「言葉の壁」につまずかなくなります。
「成功体験」を早く得られるのも大きい。最初の合格は、その後の学習を続けるモチベーションになります。

### IT/開発の実務経験がある → **SAAから直接でOK**

基礎的なIT知識（ネットワーク、サーバ、DB、Webの仕組み）があるなら、CLFを飛ばしてSAAから狙って問題なし。
市場価値の高いSAAを最初の目標にする方が効率的。
ただし「ITは長いがクラウドは初めて」という人は、**最初の1〜2週間でCLF範囲の概念だけ流し見**しておくと、SAAの土台が安定します（受験はしなくてよい）。

### 自信がない・転職活動が近い → **CLF→SAAの順で両方**

CLFで足場を固め、SAAで勝負。履歴書に2つ書けるのも悪くない。
転職活動が「3ヶ月後」など期限つきなら、CLFを1ヶ月で取って弾みをつけ、残りでSAAに集中する、という時間配分が現実的です。

> 💼 現場の本音：採用で評価されるのは圧倒的にSAA以上。CLFは「入門の証明」として、未経験者の足場固めに価値があります。実務経験者の職務経歴書にCLFだけが書いてあると、正直「で、設計はできるの？」と思われがちです。

### タイプ別 早見表

| あなたのタイプ | 最初に受ける | 理由 |
|---|---|---|
| 完全未経験・非IT | CLF | 用語と全体像に慣れる。成功体験を得る |
| IT実務経験あり（クラウド初） | SAA（CLF範囲は流し見） | 基礎は土台がある。市場価値を優先 |
| IT実務経験あり（クラウド経験も） | SAA直行 | CLFは不要なことが多い |
| 自信なし・転職が近い | CLF→SAA | 段階的に積み上げ、履歴書も厚くする |

## 何時間で受かる？（目安）

あくまで目安です。前提知識で大きく変わります。下の数字は「合格ラインに届く」までの**累計学習時間の目安**です。

| 資格 | 実務経験あり | 未経験 |
|---|---|---|
| **CLF** | 15〜25時間 | 30〜50時間 |
| **SAA** | 50〜80時間 | 100〜150時間 |

> 「働きながら週6〜8時間」なら、CLFは1ヶ月弱、SAAは2ヶ月前後が現実的なラインです。

### 期間に落とし込むと（週あたりの学習時間別の目安）

SAA（未経験・累計120時間と仮定）を例にすると、ペースでこれだけ変わります。

| 週あたり学習時間 | SAA合格までの目安期間 |
|---|---|
| 週5時間 | 約6ヶ月 |
| 週10時間 | 約3ヶ月 |
| 週15時間 | 約2ヶ月 |
| 週20時間（短期集中） | 約1.5ヶ月 |

「1日30分を毎日」より「週末にまとめて3〜4時間」の方が、設計系のSAAは頭に残りやすい印象です。細切れだと、前回の内容を思い出すだけで時間が溶けます。

## 受験の実務：申し込みから当日まで

意外と「勉強以外」でつまずく人がいます。流れを把握しておきましょう。

1. **AWS認定アカウントを作る**（試験予約サイトに登録）
2. **試験方式を選ぶ**：テストセンター受験か、自宅でのオンライン監督付き受験か
3. **日程を予約**：人気日程は埋まりやすいので早めに
4. **当日**：本人確認書類が必須。オンライン受験は静かな個室・机の上に物を置かない等のルールが厳しい
5. **結果**：合否は会場・オンラインともに後日スコアレポートで詳細が届く形が一般的

> 💡 オンライン受験は手軽ですが、「カメラで部屋を映す」「他人が入室したら失格」など規則が細かい。初受験で緊張したくない人は、テストセンターの方が無難です。

※受験料・試験時間・問題数・合格スコアなどの条件は変動します。**申し込み前に必ず公式の最新情報を確認**してください。

## 失敗しない進め方

1. **目的を決める**：転職目的ならSAAを主目標に
2. **教材は最小限**：参考書/動画1つ＋問題集1〜2つ＋ハンズオン
3. **問題演習を主役に**：インプットだけで満足しない
4. **必ず手を動かす**：無料利用枠で実際に触る（課金アラート設定を忘れずに）

### 教材の組み合わせ例（増やしすぎない）

| 役割 | 例 | コメント |
|---|---|---|
| メインのインプット | 定番の参考書 or 動画コース 1つ | 複数買うと積ん読になる。1つを2周 |
| 問題演習 | 模擬問題集 1〜2つ | ここが合否を分ける。最低2周 |
| 手を動かす | AWS無料利用枠 | VPC・EC2・S3・IAMを実際に作る |

「教材を5つ買って満足する」のが典型的な失敗です。**1つを完璧にする方が、5つを薄く触るより強い**。

### 必ずやる：課金アラートの設定

ハンズオンで一番怖いのが「気づかぬ課金」。練習用アカウントでは、最初に予算アラートを設定しておきましょう。CLI例（しきい値は各自の予算に合わせて調整。設定値はあくまで例）。

```bash
# 例：月額の予算を作り、しきい値超過でメール通知（数値・メールは各自で変更）
aws budgets create-budget \
  --account-id 123456789012 \
  --budget '{
    "BudgetName": "monthly-learning-budget",
    "BudgetLimit": { "Amount": "10", "Unit": "USD" },
    "TimeUnit": "MONTHLY",
    "BudgetType": "COST"
  }' \
  --notifications-with-subscribers '[
    {
      "Notification": {
        "NotificationType": "ACTUAL",
        "ComparisonOperator": "GREATER_THAN",
        "Threshold": 80,
        "ThresholdType": "PERCENTAGE"
      },
      "Subscribers": [
        { "SubscriptionType": "EMAIL", "Address": "you@example.com" }
      ]
    }
  ]'
```

コンソールから「AWS Budgets」で同じ設定がGUIでもできます。CLIが不安なら無理せずGUIで。**「練習で月数万円の請求が来た」は実在する事故**なので、ここは必ず最初に。

### つまずきポイント（先に知っておくと得）

- **IAMが分かりにくい**：ユーザー/グループ/ロール/ポリシーの区別はCLF・SAA両方で頻出。早めに手で作って体感する。
- **似たサービスの混同**：SQSとSNS、EBSとEFSとS3、ELBの種類など。「何が違って、いつどっちを使うか」を表で自分なりに整理する。
- **問題文の読み違い**：SAAは「最もコスト効率が良いのは」「最小限の運用で」など条件語がカギ。条件を見落とすと正解を選べない。

## 想定FAQ

**Q. CLFを飛ばしてSAAから受けても、CLFの内容は身につく？**
A. はい。SAAの学習にはCLF範囲（概念・主要サービス・責任共有モデル）が含まれます。実務経験者なら飛ばして問題ありません。

**Q. CLFは履歴書に書く価値がない？**
A. 未経験者にとっては「学習を始めた証明」として一定の価値があります。ただし実務経験者がCLFだけ書くと物足りなく見えるので、SAA以上を目指しましょう。

**Q. 数学やプログラミングは必要？**
A. CLF・SAAともに不要です。コードを書く試験ではありません（開発寄りはDVA）。

**Q. 英語は必要？**
A. 試験は日本語でも受けられます。ただし一部の設問は翻訳が硬く読みにくいことがあるので、英語の用語に慣れておくと有利です。

**Q. 古いバージョンの試験を勉強してしまわない？**
A. 試験は定期的に改定されます。教材は**現行バージョン対応のもの**を選び、出題範囲は公式のガイドで確認しましょう。

## まとめ

- **未経験ならCLFから、実務経験があればSAAから直接**
- 時間の目安：CLFは15〜50時間、SAAは50〜150時間（前提知識で大きく変わる）
- 採用で効くのはSAA以上。CLFは足場固めに価値あり
- どちらにせよ「問題演習＋ハンズオン」が合格の鍵
- 受験料・範囲・条件は変動するので**公式で最新を確認**する

迷ったら、**まず無料利用枠でAWSを触ってみる**のが一番。自分のレベル感がつかめて、進め方が見えてきます。手を動かして「楽しい」と思えたら、その勢いでCLFかSAAに申し込んでしまいましょう。
