## はじめに：「インプットはしたのに模試で取れない」

「参考書は読んだ。動画も見た。なのに模試をやると6割止まり…」
SAA学習者の多くがぶつかる壁です。これは**才能や勉強量の問題ではなく、やり方の問題**であることがほとんど。
点が取れない人に共通する5つのパターンと、その処方箋を示します。

## 共通パターン5つ

### パターン①：インプット偏重、演習不足
参考書を完璧にしようとして、問題を解く量が圧倒的に足りない。
→ **処方箋**：インプット3：演習5の比率に。**問題を解きながら覚える**に切り替える。

### パターン②：答えの「丸暗記」
「この問題の答えはB」と覚えるだけ。少し問われ方が変わると崩れる。
→ **処方箋**：**「なぜBなのか」「なぜA・C・Dは違うのか」**まで説明できるようにする。これが本物の理解。

### パターン③：間違いを分析していない
解いて丸付けして終わり。同じ間違いを繰り返す。
→ **処方箋**：間違いを **「知らなかった／読み間違えた／迷って外した」** に分類。分類ごとに対策が違う。

### パターン④：問題文を正確に読めていない
「最もコスト効率が良い」「最小の運用で」などの**条件語**を見落とす。
→ **処方箋**：条件語に線を引く癖をつける。同じサービスでも条件で正解が変わる。

### パターン⑤：サービスの「目的の違い」が曖昧
マルチAZとリードレプリカ、SQSとSNS…の違いが混ざっている。
→ **処方箋**：混同ペアを「目的」で整理した早見表を作り、繰り返し確認する。

## 点が伸びる人の勉強サイクル

```
1. 問題を解く
2. 答え合わせ＋「なぜ」を確認
3. 間違いを3分類してノート化
4. 弱いカテゴリを参考書/ハンズオンに戻って復習
5. 再度同じ範囲を解く（定着確認）
```

このサイクルを回すと、**点数は後からついてきます**。

## 「2択で迷う」を減らすには

本番でもよくある「最後の2択」。ここで効くのが**AWSの思想**：
- コスト最適化／マネージドサービス優先／最小権限／疎結合・冗長化

迷ったらこの思想に照らすと、正解に寄せられます。

## メンタル面のアドバイス

- 模試の点数に一喜一憂しない。**伸びしろの地図**だと捉える
- 6割→8割は、正しいやり方なら**短期間で到達できる**
- 「分からない」は悪ではない。分からないを潰すのが勉強

## まとめ

模試で取れない原因は、たいてい次の5つ：
1. 演習不足 → 演習を主役に
2. 丸暗記 → 「なぜ」を説明できるように
3. 間違いを分析しない → 3分類でノート化
4. 問題文を読めていない → 条件語に線を引く
5. 目的の違いが曖昧 → 早見表で整理

やり方を変えれば、点数は必ず伸びます。焦らず、サイクルを回していきましょう。
