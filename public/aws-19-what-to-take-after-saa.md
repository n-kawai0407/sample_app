## はじめに：SAAの次、何を取る？

SAAに合格すると、多くの人がこう思います。「次は何を取ればいいんだ？」
AWS認定は12種類以上。やみくもに取っても効率が悪い。
**あなたのキャリアの方向性**から逆算するのが正解です。タイプ別に示します。

## AWS認定の全体像（ざっくり）

```
        Foundational     CLF
            ↓
        Associate    SAA / DVA / SOA
            ↓
        Professional   SAP / DOP
            ↓
        Specialty    セキュリティ / ネットワーク / 機械学習 など
```

## キャリア別おすすめルート

### ① アーキテクト / 設計を極めたい → **SAP（Solutions Architect Professional）**
SAAの上位。より複雑・大規模な設計を問われる難関だが、**市場価値は非常に高い**。
「設計で食っていく」なら王道。

### ② 開発者 / アプリエンジニア → **DVA（Developer Associate）**
Lambda、DynamoDB、CI/CDなど**開発寄り**の内容。アプリ開発者がAWSを武器にするのに最適。
SAAと範囲が重なるので比較的取りやすい。

### ③ 運用 / SRE / インフラ → **SOA（SysOps Administrator）→ DOP（DevOps Professional）**
監視・運用・自動化が中心。**運用・DevOpsを極める**ルート。
DOPはProfessionalで高く評価される。

### ④ 専門分野で尖りたい → **Specialty**
- セキュリティを極める → **Security Specialty**
- ネットワークの専門家 → **Advanced Networking**
- 機械学習・データ → **Machine Learning / Data系**
ニッチだが**希少価値が高く、単価に直結**しやすい。

## 選び方の判断軸

```
Q. 今の/目指す仕事は「設計」中心？
   └─ YES → SAP

Q. 「開発（コードを書く）」中心？
   └─ YES → DVA

Q. 「運用・自動化・DevOps」中心？
   └─ YES → SOA → DOP

Q. 特定領域（セキュリティ/NW/ML）を武器にしたい？
   └─ YES → 該当のSpecialty
```

## 資格ハンターにならないために

> 💼 現場の本音：資格を**並べるだけ**の人より、**1つの分野を深く理解して手を動かせる**人が評価されます。

- 「次の資格」より「今の資格を実務で使う」方が価値が高い場面も多い
- 資格はキャリアの**方向性を示す道具**。手を動かす経験とセットで価値が出る
- 闇雲なコレクションでなく、**目指す姿から逆算**して選ぶ

## まとめ

- SAAの次は**キャリアの方向で選ぶ**
  - 設計 → SAP / 開発 → DVA / 運用 → SOA→DOP / 専門 → Specialty
- 資格を並べるより「深く理解して使える」が評価される
- 目指す姿から逆算するのが、遠回りしないコツ

あなたが「どんなエンジニアになりたいか」。それが、次の資格を教えてくれます。
