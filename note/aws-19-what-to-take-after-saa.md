# SAAの次に取るべき資格の選び方【キャリア別】

## はじめに：SAAの次、何を取る？

SAAに合格すると、多くの人がこう思います。「次は何を取ればいいんだ？」
AWS認定は10種類以上あり、やみくもに取っても効率が悪い。しかも上位資格ほど学習コストが跳ね上がるので、「なんとなく難しそうなSAPへ」と進むと、途中で息切れしがちです。

正解は、**あなたのキャリアの方向性から逆算する**こと。
「どんなエンジニアとして評価されたいか」を決めれば、次の資格は自然に絞れます。タイプ別に、難易度感・学習時間の目安・SAAとの範囲の重なりまで含めて示します。

## AWS認定の全体像（ざっくり）

```
        Foundational     CLF
            ↓
        Associate    SAA / DVA / SOA
            ↓
        Professional   SAP / DOP
            ↓
        Specialty    セキュリティ / ネットワーク / 機械学習 / データ系 など
```

レベルが上がるほど「サービスを知っている」から「複雑な要件を設計・運用できる」へと問われ方が変わります。Specialtyは横方向の専門特化で、必ずしもProfessionalの後に取る必要はありません。

※認定の構成・名称・有効期限などは改定されることがあります。**最新は必ずAWS公式（AWS Certification）で確認**してください。

## キャリア別おすすめルート

### ① アーキテクト / 設計を極めたい → **SAP（Solutions Architect Professional）**

SAAの上位。より複雑・大規模・マルチアカウント/マルチリージョンの設計や、移行・コスト最適化・組織統制（Organizations、SCP等）が問われる難関。**市場価値は非常に高い**。
「設計で食っていく」なら王道です。

- SAAとの重なり：大きい。SAAの知識を「複雑な要件で組み合わせる」方向に深掘りする
- 学習時間の目安：**100〜150時間程度**（SAA合格直後ならもう少し短いことも）
- 注意：問題文が長く、英語的に硬い設問もある。「読む体力」が要る

### ② 開発者 / アプリエンジニア → **DVA（Developer Associate）**

Lambda、DynamoDB、API Gateway、SQS/SNS、CI/CD（CodeシリーズやSAM）など**開発寄り**の内容。アプリ開発者がAWSを武器にするのに最適。

- SAAとの重なり：そこそこある（VPC、IAM、S3などの基礎は共通）ので、SAA直後だと取りやすい
- 学習時間の目安：**40〜80時間程度**
- 向く人：日常的にコードを書く人。サーバレス中心の開発をしている人

### ③ 運用 / SRE / インフラ → **SOA（SysOps Administrator）→ DOP（DevOps Professional）**

監視・運用・自動化・インシデント対応が中心。**運用・DevOpsを極める**ルート。
SOAで運用基礎を固め、DOP（Professional）でCI/CD・自動化・可観測性を深める流れが王道。

- SAAとの重なり：SOAはSAAと範囲が重なる部分が多い
- 学習時間の目安：SOAは**50〜80時間程度**、DOPは**100〜150時間程度**
- 向く人：CloudWatch・Systems Manager・IaC（CloudFormation/Terraform）を触る運用・SRE職

### ④ 専門分野で尖りたい → **Specialty**

- セキュリティを極める → **Security Specialty**
- ネットワークの専門家 → **Advanced Networking Specialty**
- 機械学習・データを武器に → **Machine Learning / データ系のSpecialty**

ニッチだが**希少価値が高く、単価に直結**しやすい。すでに実務でその領域を触っている人ほど有利です。

- SAAとの重なり：領域による（ネットワーク・セキュリティはSAAの延長で入りやすい）
- 学習時間の目安：**領域と実務経験次第で大きく変動**（実務未経験だと長くなりがち）
- 向く人：「この領域なら任せろ」という看板を作りたい人

## ルート別 比較表（目安）

| 次の資格 | レベル | SAAとの重なり | 学習時間の目安 | こんな人に |
|---|---|---|---|---|
| SAP | Professional | 大 | 100〜150h | 設計・アーキテクトで上を目指す |
| DVA | Associate | 中 | 40〜80h | コードを書く開発者 |
| SOA | Associate | 大 | 50〜80h | 運用・SREの基礎を固めたい |
| DOP | Professional | 中（SOA/DVAの先） | 100〜150h | DevOps・自動化を極める |
| Specialty各種 | 横の専門 | 領域による | 領域・経験次第 | 特定領域の看板が欲しい |

※学習時間はあくまで目安。前提知識・実務経験で大きく変わります。受験料や試験範囲は**公式で最新を確認**してください。

## 選び方の判断軸

```
Q. 今の/目指す仕事は「設計」中心？
   └─ YES → SAP

Q. 「開発（コードを書く）」中心？
   └─ YES → DVA

Q. 「運用・自動化・DevOps」中心？
   └─ YES → SOA → DOP

Q. 特定領域（セキュリティ/NW/ML/データ）を武器にしたい？
   └─ YES → 該当のSpecialty

Q. どれもピンとこない／まだ実務が浅い？
   └─ まず「今のSAAを実務で使う」。資格より手を動かす経験を積む
```

### ケーススタディ：3人の「SAAの次」

実際にありそうな3パターンで考えてみます。

- **Aさん（受託開発のバックエンドエンジニア）**：日々Lambdaとデータ処理を書いている。→ 迷わず**DVA**。学んだことが翌日の業務に直結し、学習効率が高い。
- **Bさん（社内インフラ担当、運用が主業務）**：監視・障害対応・パッチ適用が中心。→ **SOA**で運用知識を体系化し、その先で**DOP**を見据える。SAA直後なので重なりも活きる。
- **Cさん（転職してアーキテクトを名乗りたい）**：設計提案で評価されたい。→ **SAP**。難関だが、職務経歴書での説得力が段違い。ただし実務での設計経験とセットでないと「資格倒れ」に見える点に注意。

同じ「SAA合格者」でも、最適な次の一手はこれだけ違います。

## 資格ハンターにならないために

> 💼 現場の本音：資格を**並べるだけ**の人より、**1つの分野を深く理解して手を動かせる**人が評価されます。面接で資格の数を自慢されるより、「この設計をなぜこうしたか」を語れる人の方が、はるかに信頼されます。

- 「次の資格」より「今の資格を実務で使う」方が価値が高い場面も多い
- 資格はキャリアの**方向性を示す道具**。手を動かす経験とセットで価値が出る
- 闇雲なコレクションでなく、**目指す姿から逆算**して選ぶ
- 取った資格は**有効期限（一般に3年程度。最新は公式で要確認）**があり、再認定が必要。「使わない資格を量産」するとメンテだけが負担になる

### 資格を「実務で使う」具体例

資格を腐らせないコツは、学んだ概念を小さくても実物に落とすこと。たとえばSAAの知識を、自分の検証用アカウントでIaC（Terraform）として書いてみるだけでも定着が違います。

```hcl
# 例：SAAで学ぶ「マルチAZ構成」を最小構成で書いてみる（学習用の最小例）
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}

resource "aws_subnet" "public_a" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.1.0/24"
  availability_zone = "ap-northeast-1a"
}

resource "aws_subnet" "public_c" {
  vpc_id            = aws_vpc.main.id
  cidr_block        = "10.0.2.0/24"
  availability_zone = "ap-northeast-1c"
}
# 2つのAZにサブネットを分ける、という「設計の理由」を手で確かめるのが目的
```

「試験で覚えたマルチAZを、実際にコードで2つのAZに分けてみる」。この一手間が、面接で語れる経験に変わります。

## 想定FAQ

**Q. SAAの次は必ずProfessional（SAP/DOP）に進むべき？**
A. いいえ。開発者ならDVA、運用ならSOAの方が業務に直結します。Professionalは「設計/DevOpsで上を目指す」人向け。背伸びして取っても実務で使わなければ宝の持ち腐れです。

**Q. SAPとDOP、両方取る意味はある？**
A. 設計も運用も担うリードエンジニアなら価値があります。ただしどちらも難関なので、まずは自分の主戦場に近い方から。

**Q. Specialtyはいきなり受けてもいい？**
A. 受けられます。ただし実務経験がないと合格は厳しめ。普段触っている領域を選ぶのが鉄則です。

**Q. 資格より実務経験、と言うなら資格は無駄？**
A. 無駄ではありません。学習で体系的に穴を埋められ、転職時の足切り回避にもなります。「実務とセットで効く」と捉えるのが正解です。

## まとめ

- SAAの次は**キャリアの方向で選ぶ**
  - 設計 → SAP / 開発 → DVA / 運用 → SOA→DOP / 専門 → Specialty
- 学習時間の目安：DVA・SOAは数十時間、SAP・DOPは100時間超（前提次第）
- 資格を並べるより「深く理解して使える」が評価される
- 有効期限・再認定があるので、**使う資格を選ぶ**のが賢い
- 目指す姿から逆算するのが、遠回りしないコツ

あなたが「どんなエンジニアになりたいか」。それが、次の資格を教えてくれます。
