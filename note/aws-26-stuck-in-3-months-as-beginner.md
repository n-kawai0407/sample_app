# 未経験からAWS実務に入って3ヶ月で詰んだこと

## はじめに：資格を取って現場に入った、そのあと

未経験からクラウドを学び、資格も取って、念願のAWS実務へ。
最初はワクワク。でも3ヶ月もすると、現実の壁に次々ぶつかります。

これは私が（そして多くの未経験スタートの人が）通った道。
**「詰んだこと」と「どう抜けたか」**を、できるだけ正直に、具体的なエピソード込みで書きます。これから現場に入る人の心の準備になれば。

先に結論だけ言うと——**詰まるのは異常ではなく通過点**です。問題は詰まったときの「動き方」を知っているかどうか。その動き方を5つの場面ごとに残します。

## 詰んだこと①：用語は知っているのに、会話についていけない

資格で用語は覚えた。でも現場の会話は速い。

> 「そこVPCピアリングで、TGW経由にして、SGはALB参照で、あとはRoute 53のweighted回しといて」

**単語は分かるのに、組み合わさると意味が取れない**。会議で何度も置いていかれました。
ある日のスタンドアップで「で、ナオトさん的にはどう？」と振られ、固まって何も言えなかったのは今でも覚えています。

→ **抜け方**：
- 分からない単語・構成は**その場でメモ**し、会議後に必ず調べてノート化
- 「分かったフリ」をやめて、勇気を出して質問する（「TGW経由というのは、ピアリングの代わりに集約してるという理解で合ってますか？」のように**自分の理解を添えて**聞くと、相手も答えやすい）
- 議事録係を買って出る。聞き逃せない立場になると、用語の解像度が一気に上がる

**聞ける人は伸びます**。質問は弱さではなく、最短の学習です。

## 詰んだこと②：「自分で調べる」のレベルが想像以上

学習中はチュートリアル通りに進めればよかった。
現場では「公式ドキュメントを読んで、自分で判断する」が当たり前。
最初は**ドキュメントのどこを見ればいいかすら分からなかった**。「とりあえずブログ記事をコピペ」で動かして、後で構成がぐちゃぐちゃになる、を何度かやりました。

→ **抜け方**：
- 公式ドキュメント（特に該当サービスの「ユーザーガイド」と「APIリファレンス」）に毎日触れて慣れる
- エラーメッセージを**最後まで正確に読む**癖をつける（答えはたいていメッセージ本文に書いてある）
- 古いブログのコピペに頼らない。一次情報（公式・`aws help`）に当たる
- 調べた内容は「自分の言葉で1行に要約」してメモ。検索した瞬間に分かった気になるのを防ぐ

**ググり方・ドキュメントの歩き方も立派なスキル**です。最初から得意な人はいません。

## 詰んだこと③：本番環境の「怖さ」

学習は壊しても自分のアカウントだけ。現場は本番。
「このコマンド、本番で叩いて大丈夫か…？」と手が震える。
影響範囲が読めず、何をするにも時間がかかりました。一度、検証のつもりで叩いたコマンドのリージョンを間違えかけ、Enterの寸前で気づいて冷や汗——という経験もあります。

→ **抜け方**：
- いきなり本番を触らない。**検証環境で必ず試す**習慣
- **変更は小さく、確認しながら**。一度に複数を変えない
- 破壊的な操作の前に、影響範囲を声に出す／チャットに書く（「`xxx`を消します。参照しているのは`yyy`だけ、で合ってますか？」）
- 先輩にレビューしてもらう。IaCなら`terraform plan`／CloudFormationの変更セットで**事前に差分を確認**する安心感は絶大

```
# 本番で破壊的操作をする前のセルフチェック（口に出す）
□ 今どのアカウント・どのリージョンにいるか確認したか
□ この操作の影響範囲（誰が/何が依存しているか）を言えるか
□ 戻し方（ロールバック手順）を持っているか
□ 検証環境で同じ操作を試したか
□ レビュー/承認をもらったか
```

「怖い」と感じられているうちは、むしろ健全です。怖くなくなった頃の油断が一番危ない。

## 詰んだこと④：「資格の知識」と「現場のやり方」のギャップ

試験では「ベストプラクティス」を学ぶ。でも現場には歴史的経緯や予算・期日の制約があり、
**教科書通りでない構成**が普通にあります。「なぜこうなってるんだ？」の連続。

私の現場でも、教科書なら間違いなくマネージドサービスを使う場面で、移行コストの都合でEC2自前構築が残っている、という箇所がありました。最初は「なんで？」と思いましたが、経緯を聞くと納得の判断だったのです。

→ **抜け方**：
- 「**理想**」と「**現実の制約**」は別物だと受け入れる
- 今の構成に至った経緯を聞く（「これ、当時どういう理由でこの構成にしたんですか？」）。判断の背景が学べる
- 「自分ならこう直す」と心の中で設計し、改善提案として温めておく（いつか効く）

**教科書は出発点、現実は応用**。ギャップにモヤッとできるのは、知識がある証拠でもあります。

## 詰んだこと⑤：分からないことの量に圧倒される

学べば学ぶほど、知らないことが増えていく感覚。
「いつになったら一人前になれるんだ」と何度も思いました。AWSのサービス数だけでも膨大で、毎週のように新機能が出る。終わりが見えない。

→ **抜け方**：
- 全部を一度に理解しようとしない。**今日のタスクに必要なことから**潰す
- 「広く浅く全部」より「**目の前の1つを深く**」。点が増えればいずれ線になる
- 3ヶ月前の自分と比べる（他人や理想と比べない）。確実に成長している
- 学んだことを発信・メモする。アウトプットすると、断片がつながる

知らないことが増える感覚は、視野が広がっている証拠。**圧倒される＝成長している**、と捉え直しましょう。

## Before / After：3ヶ月の自分の変化

| 場面 | 入った直後（Before） | 3ヶ月後（After） |
| --- | --- | --- |
| 会議 | 用語が組み合わさると迷子 | 自分の理解を添えて質問できる |
| 調べ物 | ブログをコピペ | 公式とエラーメッセージを読む |
| 本番操作 | 怖くて手が止まる | チェックリストで手順化できる |
| 構成への疑問 | 「なんで？」でモヤモヤ | 経緯を聞いて判断を学ぶ |
| 知識量 | 量に圧倒される | 必要な所から1つずつ潰す |

## これから現場に入る人へのチェックリスト

```
□ 分からない用語をその場でメモする仕組みを持っているか
□ 「自分の理解を添えて質問する」言い回しを用意したか
□ 公式ドキュメント（ユーザーガイド/リファレンス）をブックマークしたか
□ 検証環境で試す習慣があるか
□ 破壊的操作前のセルフチェックを持っているか
□ 「3ヶ月前の自分と比べる」マインドを持てているか
```

## 3ヶ月を越えて分かったこと

- 詰まるのは**当たり前**。みんな通る道
- **質問できる人・調べ続ける人**が伸びる
- 資格は無駄じゃない。**地図があるから、現場で迷っても方向が分かる**
- 完璧を目指さず、**昨日より一歩**でいい
- 「怖い」「分からない」を感じられること自体が、誠実に向き合えている証拠

## まとめ

未経験から現場に入ると、必ず詰まります。でもそれは成長痛です。

1. 会話についていけない → 理解を添えて聞く・後で調べてノート化
2. 自分で調べる難しさ → 一次情報に毎日触れ、エラーを読む
3. 本番の怖さ → 検証で試す・小さく変更・事前にplanで差分確認
4. 資格と現場のギャップ → 経緯を聞き、理想と制約を分けて受け止める
5. 分からない量に圧倒 → 今必要なことから1つずつ

これから挑む人へ。**詰まっても大丈夫。それは前に進んでいる証拠です。**
