# やらかしがちなAWS課金事故とその防ぎ方【保存版】

## はじめに：AWSの怖さは「気づいたときには遅い」こと

クラウドの便利さの裏側に、**「使った分だけ課金される」**という現実があります。
学習目的でちょっと触っただけのつもりが、月末に予想外の請求 ── これは合格者でも、現役エンジニアでもやらかします。

この記事では、**よくある課金事故TOP5**と、その**確実な防ぎ方**をまとめます。これからAWSを学ぶ人は、手を動かす前に必ず読んでください。

## 事故TOP5（あるある順）

### ① NATゲートウェイの消し忘れ
作ったまま放置すると、**何もしなくても時間課金**され続けます。検証でVPCを作ると一緒に立てがち。
→ **対策**：検証後は必ず削除。通信先がS3/DynamoDBならVPCエンドポイントで代替できることも。

### ② Elastic IPの「未使用」課金
EIPは**インスタンスに紐づいていないと課金**されます。「確保したけど使ってない」が罠。
→ **対策**：使わないEIPは解放（Release）する。

### ③ EBS・スナップショットの残骸
EC2を消してもEBSボリュームやスナップショットが残り、ストレージ課金が続くことがあります。
→ **対策**：インスタンス削除時にボリュームも削除。不要なスナップショットは整理。

### ④ 止め忘れたRDS・EC2
検証用のDBやサーバーを起動しっぱなし。RDSは特に高くつきます。
→ **対策**：使わない時間帯は停止。検証環境は夜間・休日に自動停止する仕組みを。

### ⑤ S3への大量リクエスト/転送
ストレージ代より、**リクエスト数やデータ転送（特にインターネットへの外向き）**で積み上がることも。
→ **対策**：不要な公開・大量アクセスを避け、CloudFront等でキャッシュ。

## 最初にやるべき「3つの防御」

事故ってからでは遅い。アカウントを作ったら、**真っ先に**これを設定してください。

1. **AWS Budgets で予算アラート**
   月の予算を決め、しきい値（例：50%・80%・100%）でメール通知。
2. **Cost Explorer を週1で見る習慣**
   「何にいくらかかっているか」を体で覚える。異常にすぐ気づける。
3. **無料利用枠の超過アラート**
   Free Tierの上限に近づいたら通知してくれる設定をON。

> 💼 現場でも、新しいアカウントを払い出したらまずやるのが予算アラート設定です。「コスト管理は最初の一手」が鉄則。

## もし高額請求が来てしまったら

- まずは落ち着いて **Cost Explorer / 請求ダッシュボード**で原因サービスを特定
- 学習中の予期せぬ高額請求は、**サポートに相談すると一度は減免されるケースもある**（保証はされません）
- 二度と繰り返さないよう、予算アラートを必ず入れる

## まとめ

- AWSは「使った分だけ課金」。消し忘れ・止め忘れが事故の主因
- **NATゲートウェイ / EIP / EBS / 起動しっぱなし / 転送量**に注意
- **アカウント作成直後に予算アラート＋Cost Explorer習慣**で大半は防げる

楽しくAWSを学ぶために、まず「お財布の守り」を固めましょう。
